# 架构说明

## 目标

在 1 MB APK、零第三方依赖的约束下，用纯 CPU 实现可玩的实时 3D 第一人称游戏。

## 分层

```
┌──────────────────────────────────────────────┐
│ Android 壳层                                  │
│ MainActivity → GameView(SurfaceView + 线程)   │
│   ├─ 输入（摇杆 / 滑动 / 按钮 / 键盘）          │
│   ├─ 自适应内部分辨率                          │
│   └─ Hud（软件 Canvas）                        │
├──────────────────────────────────────────────┤
│ engine（纯 Java，可无头运行）                   │
│   Raycaster → int[] ARGB 帧缓冲                │
│   Game → 世界状态与规则                         │
│   MapGen / Textures / Rng                     │
└──────────────────────────────────────────────┘
```

`engine` 不 import 任何 `android.*`，因此能在桌面 JVM 上编译、跑逻辑测试并输出 PNG 做视觉回归。

## 单帧数据流

1. `Game.update(dt)`：输入 → 玩家移动/开火 → 敌人 AI → 拾取 → 粒子 → 状态机
2. `Raycaster.render(game, fb, w, h, time)`：
   - 逐行绘制天花板与地板（反向投影 + 逐行距离光照）
   - 逐列 DDA 求墙，写入 z-buffer 与纹理采样
   - 收集广告牌（传送门 / 核心 / 无人机 / 粒子），按距离从远到近插入排序
   - 逐列 z 测试后 alpha 混合
3. `Bitmap.setPixels(fb)` → `Canvas.drawBitmap` 最近邻放大到全屏
4. `Hud.draw(canvas, ...)`：血条、核心、小地图缓存、准星、枪械、状态遮罩

## 关键决策

- **整数像素缓冲而非 Android Canvas 3D**：可精确控制每个像素与性能，避免 GPU 依赖。
- **程序化素材**：省掉全部图片资源，也保证 APK 体积可控；纹理/精灵由种子决定，可复现。
- **内部低分辨率 + 最近邻放大**：像素风观感与性能兼得；分辨率随实测帧耗时自适应。
- **SurfaceView 独立渲染线程**：UI 线程只处理输入，避免掉帧卡顿。
- **MapGen 连通修复**：环切/房间雕刻后对不可达地板做 L 型回填，保证核心、出口、敌人刷新点永远可达。

## 性能预算（开发机 x86，480×270 = 129,600 px）

| 阶段 | 耗时 |
| --- | --- |
| `Game.update` + `Raycaster.render` | ≈ 1.3 ms/帧 |
| 帧缓冲上传 + 缩放 | 取决于屏幕分辨率（软件拷贝） |

移动端通过 `sceneMs` 滑动平均调节内部宽度（240–560），阈值 6.5 ms / 11 ms，1.2 s 冷却。
