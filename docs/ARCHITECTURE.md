# 架构说明（v3）

## 目标

在 1 MB APK、零第三方依赖、纯 CPU 的约束下，实现真 3D 第一人称游戏：自由俯仰、高差台阶、跳跃/下蹲，同时保持 60 FPS 目标。

## 分层

```
┌─────────────────────────────────────────────────┐
│ Android 壳层                                     │
│ MainActivity → GameView(SurfaceView + 渲染线程)   │
│   ├─ 输入：摇杆 / 滑动(转向+俯仰) / 跳跃 / 下蹲    │
│   ├─ 自适应内部分辨率                             │
│   └─ Hud（软件 Canvas）                           │
├─────────────────────────────────────────────────┤
│ engine3d（纯 Java，可无头运行）                    │
│   Game3D → 物理 / AI / 拾取 / 状态机              │
│   Renderer3D → 裁剪 / 光栅化 / z-buffer / 广告牌   │
│   MeshBuilder3D + MapGen3 → 高度场几何            │
│   Camera3D / MipTextures                          │
├─────────────────────────────────────────────────┤
│ engine（基础类型）                                 │
│   Textures / Sprite / Enemy / Pickup / Particle    │
└─────────────────────────────────────────────────┘
```

## 单帧数据流

1. `Game3D.update(dt)`
   - 输入 → 俯仰/转向 → 水平移动（台阶检查）→ 重力/跳跃 → 蹲伏视点插值
   - 无人机：BFS 流场 + 视线检测 + 分离 + 悬浮高度平滑
   - 3D 射线命中（yaw ± pitch，胶囊近似）→ 伤害 / 粒子
   - 读取拾取、传送门、状态机
   - `buildBillboards()` 复用对象池填充精灵列表
2. `Camera3D.update(w)`：由 yaw/pitch 构建 forward/right/up，focal = (w/2)/tan(hfov/2)
3. `Renderer3D.render(...)`
   - 相机空间变换 → 四顶点近平面裁剪（Sutherland–Hodgman）
   - 投影 → 边函数三角形 → 1/z 深度测试 → 透视校正纹理 + mip + 雾
   - 广告牌按距离从远到近排序，逐像素 alpha 混合
4. `Bitmap.setPixels` → 软件 Canvas 最近邻放大
5. `Hud.draw`：血条、核心、小地图、准星、枪械、跳跃/下蹲键、彩蛋状态

## 关键决策

- **地形用高度场而非任意网格**：每格一个 0.25 m 量化高度 → 生成地板/台阶/墙四边形，既保留程序化迷宫，又能走楼梯、跳平台；无需 BSP/CSG。
- **逐面光照**：面法线烘焙遮光系数，雾按三角形质心计算，避免逐像素光照成本。
- **mip 链**：程序化 64×64 下采样到 8×8，远处自动降采样，既省缓存又抗闪烁。
- **广告牌 vs 实体模型**：核心/传送门/粒子继续用广告牌；敌人改为实心四边形网格，逐帧构建到可复用 `Mesh3D`，与静态几何共享 z-buffer。
- **实心面片路径**：模型面片不采样纹理，直接以面法线烘焙颜色 + 雾写像素，省掉 UV 插值与纹理取址。
- **双深度缓冲**：彩蛋透视把敌人写入独立 `zbufXray`，既穿墙又保持模型自身遮挡正确。
- **子弹**：3D 速度 + 0.1 m 子步，避免高速穿透；命中才扣血。
- **720p 固定**：取消自适应，按屏幕比例锁高度 720，便于观察纯 CPU 填充率上限。
- **台阶平滑**：BFS 生成高度后迭代把 >0.25 m 的相邻差压平，测试断言所有可走边 ≤0.26 m。
- **彩蛋与游戏逻辑解耦**：触摸层只置 `input.cheatTap`，由模拟线程切换，避免跨线程改状态。

## 性能预算（x86，480×270 = 129,600 px）

| 项目 | 数值 |
| --- | --- |
| 关卡四边形 | 约 600 |
| `update + render` | ≈ 3.1 ms/帧 |
| z-buffer / 帧缓冲 | 各约 0.5 MB |
| 自适应阈值 | 渲染 >12 ms 降档，<7 ms 升档，240–520 px |
